# DNS Watchdog для OpenWrt

Проверяет резолвинг через локальный DNS и при устойчивых ошибках переподнимает **один логический интерфейс**, например `wan`. Роутер целиком, LAN и DNS-служба не перезагружаются, если выбран именно WAN. Переподключение может оборвать VPN, звонки и другие активные соединения.

## Логика

- По умолчанию — 3 домена, запросы `A` к `127.0.0.1:53`, цикл каждые 15 секунд. Это DNS роутера, а не прямые запросы к публичным DNS.
- Таймаут одного запроса — 3 секунды. Проверки последовательные; если цикл занимает больше интервала, следующий начнётся после его завершения и паузы в 1 секунду.
- Скользящее окно — последние 4 полных цикла, то есть 12 запросов. До заполнения окна действий нет.
- Действие только при **строго более 75%** ошибок: `9/12` не срабатывает, `10/12` срабатывает. Если последний цикл полностью успешен, перезапуска нет даже при плохой истории.
- Клиент выбирается автоматически: сначала `dig`, если его нет — `nslookup`. Можно задать `DNS_CLIENT='dig'` или `DNS_CLIENT='nslookup'` явно.
- Ошибка — таймаут, ненулевой код клиента или отсутствие адреса в ответе. Для `dig` дополнительно требуется DNS-статус `NOERROR` и A/AAAA-запись нужного типа именно в секции ANSWER: код 0 при `SERVFAIL`, `NXDOMAIN`, пустой ответ или один CNAME не считаются успехом. Один лишь адрес DNS-сервера в выводе `nslookup` тоже не считается результатом.
- Принудительно выбирается один тип записи (`A` или `AAAA`), чтобы ошибка ненужного типа не портила успешную проверку другого.
- После действия окно очищается, на восстановление отводится 30 секунд. Повторное действие — не раньше чем через 300 секунд, в том числе при неудаче команды. Во время оставшегося cooldown проверки продолжаются.
- После запуска службы — пауза 60 секунд. Время отсчитывается по uptime, не зависит от NTP. История и ограничение частоты хранятся только в памяти и сбрасываются при перезапуске службы.
- **Безопасный режим по умолчанию: `DRY_RUN=1`.** Скрипт только пишет, что сделал бы. Диагностика `--check` не меняет сеть при любых настройках.

## Установка

Нужны **один из клиентов** — `dig` (BIND) или `nslookup` (BusyBox с `-type`), — а также `awk` и `sleep`. Для службы нужны `flock`, `ubus` и `ifup`, для системного журнала используется `logger`. Урезанные сборки проверьте отдельно. Внешняя команда `timeout` **не нужна**: ограничение времени DNS-запроса, проверки netifd и команды восстановления реализовано средствами shell, `sleep`, `kill` и `wait`. У `dig` дополнительно заданы собственные `+time` и `+tries=1`. Порт DNS — 53, адрес DNS-сервера задаётся как IPv4; запросы `AAAA` поддерживаются и через IPv4-транспорт.

Скопируйте `dns-watchdog.sh`, `dns-watchdog.conf`, `dns-watchdog.init` на роутер в `/tmp`, затем выполните **на роутере**:

```sh
cp /tmp/dns-watchdog.sh /usr/sbin/dns-watchdog
cp /tmp/dns-watchdog.conf /etc/dns-watchdog.conf
cp /tmp/dns-watchdog.init /etc/init.d/dns-watchdog
chmod 755 /usr/sbin/dns-watchdog /etc/init.d/dns-watchdog
chmod 600 /etc/dns-watchdog.conf
```

Перед копированием убедитесь, что не перезаписываете свои существующие файлы. Сохраняйте shell-файлы с переводами строк LF, без Windows CRLF.

В `/etc/dns-watchdog.conf` укажите:

```sh
INTERFACE='wan'
DNS_SERVER='127.0.0.1'
DNS_CLIENT='auto'
DOMAINS='openwrt.org www.cloudflare.com www.wikipedia.org'
DRY_RUN=1
```

`INTERFACE` — имя секции из `/etc/config/network`: например `wan` или `wwan`, **не** `eth0`, `pppoe-wan` или имя Wi-Fi-радио. Выбирайте всегда включённый WAN, а не LAN/управляющий интерфейс. Скрипт не предназначен для интерфейсов, которые вы намеренно отключаете вручную.

Файл конфигурации исполняется как shell-код: не давайте другим пользователям права его менять. Домены должны стабильно разрешаться в вашей сети и не блокироваться вашими DNS-фильтрами. Если локальный DNS не слушает loopback, укажите LAN-адрес роутера.

### Сначала диагностика

```sh
/usr/sbin/dns-watchdog --check
```

Один цикл без ожидания и без перезапуска. Код завершения: `0` — все имена разрешились, `1` — есть DNS-ошибки, `2` — ошибка настройки/зависимостей. Это диагностический код одного цикла, не решение по порогу скользящего окна.

Если старая версия сообщает `Required command not found: timeout`, скопируйте обновлённый `dns-watchdog.sh` в `/tmp` и замените **только скрипт**, сохранив свою конфигурацию:

```sh
/etc/init.d/dns-watchdog stop
cp /tmp/dns-watchdog.sh /usr/sbin/dns-watchdog
chmod 755 /usr/sbin/dns-watchdog
/usr/sbin/dns-watchdog --check
```

После проверки запустите службу командой `/etc/init.d/dns-watchdog start`. Устанавливать дополнительные пакеты ради `timeout` не нужно.

Запустите службу, пока ещё с `DRY_RUN=1`:

```sh
/etc/init.d/dns-watchdog enable
/etc/init.d/dns-watchdog start
logread -f -e dns-watchdog
```

Посмотрите поведение во время реального сбоя. Сообщение `DRY RUN: would restart wan` означает, что условие сработало, но сеть не менялась.

### Разрешить восстановление

После проверки установите `DRY_RUN=0` в `/etc/dns-watchdog.conf` и примените:

```sh
/etc/init.d/dns-watchdog restart
```

Восстановление выполняется командой `ifup "$INTERFACE"`: штатный OpenWrt `ifup` переподнимает логический интерфейс через netifd (down + up). Это не аппаратный сброс порта, Wi-Fi-радио, модема или зависшего драйвера.

Остановить и убрать автозапуск:

```sh
/etc/init.d/dns-watchdog stop
/etc/init.d/dns-watchdog disable
```

Не включайте одновременно другое автоматическое восстановление того же интерфейса, например правило Watchcat: независимые перезапуски усложняют диагностику.

## Важный нюанс: DNS-кэш

Постоянные имена могут обслуживаться из кэша dnsmasq/Unbound/AdGuard Home. Поэтому эта схема проверяет доступность разрешения **выбранных имён**, но не гарантирует обнаружение потери связи с внешним DNS: закэшированные ответы или режим serve-stale могут скрыть проблему.

Если нужно проверять прохождение свежих запросов наружу, можно добавить уникальные имена в **своей удалённой зоне с wildcard-записью**, например `*.dnscheck.your-domain.tld A <ваш IP>`:

```sh
DOMAINS='openwrt.org www.cloudflare.com {nonce}.dnscheck.your-domain.tld'
```

Скрипт заменяет `{nonce}` в первом компоненте имени новым UUID для каждого запроса. **Не используйте случайные поддомены обычных сайтов:** нормальный `NXDOMAIN` станет ложной ошибкой. Не отключайте и не очищайте DNS-кэш всего роутера ради watchdog. Один свежий домен из трёх при двух закэшированных успешных доменах даст лишь 33% ошибок: для надёжного контроля именно внешнего резолвинга свежими должны быть достаточно многие проверки, желательно в нескольких независимых зонах.

## Когда переподнятие WAN не поможет

DNS-сбой может быть вызван самим dnsmasq/Unbound/AdGuard Home, его DoH/DoT-прокси, DNSSEC/системным временем, фильтрами или внешним DNS. Переподнятие WAN не устраняет эти причины и при длительном сбое будет повторяться с заданным cooldown. Для начала используйте режим журналирования и сравните локальные запросы с запросами к настроенному upstream вручную. Скрипт намеренно не подменяет DNS публичным сервером и не перезапускает DHCP/DNS-службу.

Если хотите, чтобы скрипт реагировал на более редкие плавающие ошибки, уменьшите `ERROR_THRESHOLD`: при пороге >75% случаи вроде 30% неудачных запросов **не должны** вызывать восстановление.

## Проверка кода

```sh
sh -n dns-watchdog.sh
sh -n dns-watchdog.init
sh tests/test_dns_watchdog.sh
sh tests/test_timeout.sh
```

Основные тесты используют подменённые DNS-ответы, часы и команду восстановления; реальная сеть не меняется. Проверяются положительные/пустые/отрицательные ответы, таймауты, точная граница 75%, скользящее окно, восстановившийся последний цикл, cooldown, dry-run и ошибки конфигурации. `test_timeout.sh` отдельно запускает реальные короткие/долгие процессы и проверяет возврат кода, вывод, завершение по дедлайну и быструю отмену таймера без внешней команды `timeout`. Проверку на самом роутере это не заменяет.
